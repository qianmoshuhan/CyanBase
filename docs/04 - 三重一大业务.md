---
## 1. 业务对象

| 实体 | Controller | 说明 |

| ThreeBigItem | ThreeBigItemController | 三重一大事项 |

| SydydExecute | ExecuteController | 实施管理 |

---

## 2. 权限特点

所有 CRUD 写操作都在**租户侧 Controller** 里，perms 命名为：

```
sydyd:item:add    sydyd:item:edit    sydyd:item:list
sydyd:meeting:add sydyd:meeting:edit sydyd:meeting:list
sydyd:execute:add sydyd:execute:edit sydyd:execute:list
sydyd:list:list   sydyd:system:list  sydyd:topic:list
```

> 平台侧也有同名 Controller（com.cyan.controller.system / com.cyan.modules.sydyd），但实际写操作路由是租户侧的（tenant.* 前缀）。

---

## 3. 必须加 @DataScope 注解（数据权限）

三重一大业务按"本部门/本部门及以下/仅本人"控制数据可见范围：

```java
@DataScope(deptAlias = "d", userAlias = "u")
public Page<ThreeBigItem> list(...) { ... }
```

三层拦截器链生效：
1. TenantLineInnerInterceptor 自动追加 `tenant_id = 当前租户`
2. DataPermissionInterceptor 追加 `dept_id IN (...)`

---

## 4. 工作流关联（businessType = threeBigItem）

- 发起流程时 businessType = "threeBigItem"
- 前端审批表单需要关联 ThreeBigItem 表取事项名
- WorkflowInstance.fillItemNames() 已实现：从 businessKey 回填 itemName

---

## 5. 业务模块下拉接口绝对不加注解

```java
// ✅ 以下 GET 接口都是前端渲染表单/节点配置依赖，绝对不加 @RequiresPermission
GET /sydyd/system/all          // 制度下拉
GET /sydyd/list/bySystem/{id} // 按制度查事项
GET /workflow/definition/published  // 流程发起页下拉
GET /workflow/definition/{id}       // 审批表单渲染
```

**违反后果**：前端填报表单/配置节点时下拉为空，卡死整个流程！
