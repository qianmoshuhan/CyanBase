# 部门导入导出 —— 完整链路梳理 & 可复用模式

> 本文档沉淀自部门导入导出功能的完整开发过程，包含：链路总览、踩过的坑、隐性约束、
> 可直接复用的通用模式（后续用户/角色/岗位/表单/工作流等模块的导入导出可直接套）。

---

## 一、链路总览

### 1.1 导入（7 步）
前端弹窗 → 选 .xlsx 文件（el-upload auto-upload=false，on-change 存 UploadUserFile.raw） → 点"确认导入"按钮 → POST /{system|tenant}/dept/import (FormData multipart/form-data) → Controller：校验 .xlsx 格式 + 生成批次号 DEPT-IMPORT-时间-随机串 → Service：EasyExcel.read(InputStream, VO.class, ReadListener).sheet().headRowNumber(1).doRead() → 阈值校验（>5000 行拒绝；空文件拒绝） → 预加载：收集 Excel 涉及的 tenantId → 批量 list(sys_dept WHERE tenant_id IN (...)) → 逐行校验（deptCode 禁填 / 非空 / 枚举值 / 路径格式 / 上级存在 / 循环防环） → 校验失败 → 直接 return DeptImportResultVO（带 failList + Excel 真实行号）→ 事务外 → 校验全过 → TransactionTemplate.executeWithoutResult { saveBatch(toInsert, BATCH_SIZE=500) } → 事务内 → 返回 R.ok(DeptImportResultVO { totalRows, successRows, failRows, failList }) → 前端：failRows===0 关闭弹窗+刷新列表；failRows>0 ElMessageBox 弹明细（行号+错误）

text




### 1.2 导出（6 步）
前端点"导出"按钮 → GET /{system|tenant}/dept/export?deptName=&status=&tenantId=（平台侧额外接 tenantId） → Controller：生成批次号 DEPT-时间-随机串 + 设置 Content-Disposition → Service：构造 LambdaQueryWrapper（不手写 tenantId / DataScope，信任 MP 拦截器链） → TenantLineInnerInterceptor 自动追加 WHERE tenant_id = ? → DataPermissionInterceptor 自动追加用户角色 DataScope（id IN (...) / create_by = ?） → list(wrapper) → 阈值校验（>5000 行拒绝） → 内存 Map<id, SysDept> + 递归向上构造 / 分隔层级路径（防环 Set） → 枚举翻译（status 0→正常 1→停用；isBizUnit 1→是 其他→否） → EasyExcel.write(outputStream, DeptExportVO.class).sheet().doWrite(voList)

text




### 1.3 模板下载（2 步）
前端点"下载导入模板" → GET /{system|tenant}/dept/importTemplate → Controller：EasyExcel.write(outputStream, DeptImportTemplateVO.class) .registerWriteHandler(new ImportTemplateHandler()) .sheet().headRowNumber(1).doWrite(emptyList) → ImportTemplateHandler.afterSheetCreate：给状态列（E）+ 是否经营单元列（F）加 DataValidation 下拉 → 返回 DeptImportTemplate.xlsx

text




### 1.4 核心安全保障（三层拦截器天然生效）
┌─────────────────────────────────────────────────────────────┐ │ SQL 自动追加（应用层完全不需要手写） │ ├─────────────────────────────────────────────────────────────┤ │ L1 TenantLineInnerInterceptor │ │ WHERE tenant_id = 当前登录租户ID（租户侧） │ │ WHERE tenant_id = 传入的 tenantId（平台侧） │ │ admin(tenantId=0) 或平台主体自动跳过 │ │ │ │ L2 DataPermissionInterceptor │ │ WHERE id IN (用户角色 dataScope 范围内的部门ID) │ │ 或 WHERE create_by = 当前用户名 │ │ admin 自动跳过 │ │ │ │ L3 @RequiresPermission("system:dept:list") │ │ 按钮权限（list 权限即可导出/导入，不新增 export/import 权限） │ └─────────────────────────────────────────────────────────────┘

## 二、踩过的坑 & 解决方案

### 🔴 编译/运行时 Bug

| # | 坑 | 后果 | 正确做法 |
|---|------|------|------|
| 1 | **Spring AOP 自调用绕过代理**：类内部 `this.batchInsert()` 不会触发 `@Transactional` | 声明式事务完全不生效，saveBatch 不在事务里 | 用 `TransactionTemplate` 编程式事务，直接注入 TransactionTemplate，绕过代理 |
| 2 | **事务范围过大**：`@Transactional` 标在整个 importDept 上 + 校验失败 throw BusinessException | 精心构造的 failList 随异常被吞掉，前端拿不到行号明细 | 校验阶段完全在事务外，校验失败直接 return result；只有 saveBatch 进事务 |
| 3 | **Java 正则 split 写法**：`"[/\\]"` 在 Java 字符串里歧义 | 编译器 "illegal start of expression" | 写 `"[/\\\\]"`（Java 字符串 4 个反斜杠 → 正则 2 个 → 匹配字面反斜杠） |
| 4 | **Diff 替换时换行被吞** | 注释 + 下一行代码粘成一行，编译报错 | 写完 diff 后手动 Read 文件尾部确认换行完整 |
| 5 | **Controller 重复 import**：两轮改动各加了一行 `import java.util.UUID` | 编译 warning | Accept diff 后 grep 去重 |
| 6 | **ServiceImpl 残留方法**：旧的 `batchInsert()` 方法（带 `@Transactional`）没删掉 | import 已改成 TransactionTemplate，但残留方法引用了已删的 Transactional | 每次 diff 改大范围逻辑时 grep 确认旧代码真的被替换了 |
| 7 | **`dataList.indexOf(row)` 在循环内** | 5000 行时有 2500 万次 O(n) 比较 | 用带索引的 for 循环，excelRowNum = idx + 2 直接算 |

### 🟡 前端坑

| # | 坑 | 后果 | 正确做法 |
|---|------|------|------|
| 8 | **request.js 响应拦截器把 blob 当 JSON 处理** | `res.code === undefined` → 永远判失败 → Promise.reject → 前端永远报"导出失败" | 响应拦截器最开头加旁路：`if (config.responseType==='blob' \|\| ct.includes('vnd.openxmlformats')) return response` |
| 9 | **importLoading / selectedFile 没定义 ref** | `importLoading.value = true` → ReferenceError → 请求根本没发 | script 区定义好所有 ref，模板里用的变量必须有来源 |
| 10 | **el-upload 手动 :file-list + 伪对象**：`{ name, uid: Date.now() }` 每次 re-render uid 变 | 内部状态混乱 → `e.onChange is not a function` 炸掉，on-change 回调不触发 | 不传 :file-list，让 Element Plus 自己维护列表；需要清空时用 `deptUploadRef.clearFiles()` |
| 11 | **弹窗缺"确认导入"按钮** | 用户选完文件没触发后端调用的入口 | 明确分两步：选文件暂存 → 点确认按钮才提交 |
| 12 | **on-change 参数结构**：Element Plus `el-upload on-change` 回调的第一个参数是 `UploadUserFile`，不是原生 File | `uploadFile.name` 能取到但 `.raw` 才是浏览器 File 对象 | 存 `uploadFile.raw`，调后端时传 raw |

### 🟢 EasyExcel 4.0.3 版本坑

| # | 坑 | 正确做法 |
|---|------|------|
| 13 | `WriteSheetHolder.getHeadRowNumber()` 不存在 | 直接硬编码常量（VO 列数固定为 8） |
| 14 | `SheetWriteHandlerContext.getHead()` 不存在 | 同上，用固定常量 |
| 15 | `headRowNumber` 默认值 | 写入时 headRowNumber=1（EasyExcel 默认就是 1）；读取时 `.headRowNumber(1)` 显式指定 |
| 16 | DataValidation 下拉范围 | 第 2 行生效（0-based row=1）→ Excel E2:E5001 |

## 三、隐性约束（开发前必须知道）

### 3.1 必须遵守的

| # | 约束 | 原因 |
|---|------|------|
| 1 | **租户侧 / 平台侧双镜像 Controller** | 前端有两套访问入口（`/system` vs `/tenant`），两边都要有完整接口 |
| 2 | **MP 拦截器链天然生效，应用层不要手写 tenantId / DataScope 条件** | 手写会跟拦截器重复追加，导致 SQL 条件冲突；信任 TenantLineInnerInterceptor + DataPermissionInterceptor |
| 3 | **导入只支持新增，不做更新** | 设计决策：dept_code 由系统生成，不提供外部更新入口 |
| 4 | **前端不校验 Excel 下拉** | 浏览器打开文件时下拉可能丢失（如在线文档编辑），全部校验必须在后端 |
| 5 | **事务粒度：只有写 DB 才进事务** | 校验阶段无 DB 写操作，不需要事务；事务范围大了会浪费连接 + 锁资源 |
| 6 | **批次号必须生成 + log.info 记录** | 操作日志 sys_oper_log 通过 `@Log` 注解写，但批次号是跨多条日志串联的唯一标识 |
| 7 | **阈值 5000 行** | 导入导出共用，超过给友好提示，不要让请求超时 |
| 8 | **权限码复用 `system:dept:list`** | 不新增 export/import 独立权限点（避免菜单漏分配），能查看就能导出/导入 |

### 3.2 隐性行为（容易忽略但不会报错）

| # | 行为 | 说明 |
|---|------|------|
| 1 | MP TenantLineInnerInterceptor 对 admin(tenantId=0) 自动跳过 | admin 用户查 sys_dept 会拿到全租户数据 |
| 2 | 平台侧导入时 Excel 的 tenantId 列必填 | 租户侧完全忽略（强制用 SecurityUtils.getTenantId()） |
| 3 | resolveParentId 找不到路径里的上级时，从后往前找最后一个已存在的部门作为 parent | 路径 "A/B/C/D"，只有 "A" 存在 → 新增部门 parentId = A.id（不是顶级） |
| 4 | DataScope 的 SELF / DEPT / DEPT_AND_CHILD / ALL 范围 | 导入时 list() 被 DataScope 限制 → 路径匹配只能匹配到用户权限范围内的部门（不在范围的部门匹配不到 → 校验失败 → 不会写入） |
| 5 | `@Log(isSaveRequestData = false)` | 导入/导出不保存 request body（文件流或大 query param 没必要，也避免日志表膨胀） |
| 6 | dept_code 用 UUID 去横线生成 | 不查库判重，依赖数据库 `uk_tenant_dept_code(tenant_id, dept_code)` 唯一索引兜底 |
| 7 | EasyExcel ReadListener 的 invoke 是流式逐行回调 | 但为了能统一做阈值校验 + 预加载，先收集全量再处理 |

## 五、后期可增强的点

| # | 增强 | 当前状态 | 说明 |
|---|------|----------|------|
| 1 | 同名多部门歧义精确匹配 | 简化处理（同名就算通过） | 路径 "A/B" 有两个 B 时，按 parentId 层级精确匹配 |
| 2 | 部门名唯一性校验 | 暂不做 | 同租户内 deptName 重复提示 |
| 3 | 大文件异步导入（上传→后台处理→轮询结果） | 同步等待 | 超过 5000 行 / 10000 行阈值时异步 |
| 4 | 导入历史查询页面 | 无 | 利用 sys_oper_log 的 businessType=IMPORT + batchNo 过滤 |
| 5 | DataScope 路径匹配范围 | 按用户权限内的部门做路径匹配 | 路径上级不在权限范围 → 匹配不到 → 校验失败（安全但可能误拦） |
| 6 | 乐观锁处理（导入过程中已有数据变更） | 无 | 批量入库可能与并发请求冲突 → saveBatch 默认 insert |
| 7 | 导入进度条 | 无 | 大文件导入时前端显示进度 |
| 8 | 单测覆盖 | 无 | validatePath 防环、resolveParentId 解析逻辑值得补 |
