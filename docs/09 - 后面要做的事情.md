## 4. 验收 Checklist（流程保存逻辑每次改动必跑） [R]

> 以后每次改流程保存逻辑都必须跑以下检查项：

| # | 验收项 | 验证方式 |
|---|--------|----------|
| 1 | 租户侧新建流程 → 保存 → 重新打开 → 节点表格顺序与编辑时一致 | 手动操作 + DB 查询 |
| 2 | 租户侧编辑已有流程 → 中间 + 新增/删除/移动 → 保存 → 重新打开 → 顺序正确 | 同上 |
| 3 | BPMN 预览：节点链路正确（nextNodeIds 引用的 ID 全部是新自增 ID） | 浏览器 F12 + 设计器预览 |
| 4 | 流程预览（非 BPMN）：表格顺序按 sortOrder ASC 与编辑时一致 | 浏览器表格直接看 |
| 5 | 数据库直接查 `SELECT id, sort_order FROM wf_process_node WHERE definition_id = ? ORDER BY sort_order` → sort_order 连续 1,2,3... 无跳号 | MariaDB 命令行 |
| 6 | 平台 admin 编辑同一流程 → 保存 → 租户侧再打开 → 不串数据、节点正确 | 双账号验证 |
| 7 | `npm run build` 过 + `mvn clean compile` 过 | 编译验证 |
| 8 | **WorkflowNode.sortOrder 唯一约束 + 自动重排** | DB + 后端 | 可以在 DB 层加 `UNIQUE(definition_id, sort_order)` 索引防止脏数据；后端保存时用一个 `UPDATE wf_process_node SET sort_order = sort_order + 1 WHERE definition_id = ? AND sort_order >= ?` 的方式支持中间插入 |
| 9 | **前端新增节点时 sortOrder 按插入位置重编** | 前端设计器 | 当前 addNode() 永远赋 length+1，保存时虽然后端会重编，但编辑中间节点时表格显示的顺序已经是对的（因为按数组位置）；可以优化为：splice 插入后立即 forEach 重新编整个数组的 sortOrder，让编辑时的表格 sortOrder 列也连续 |
| 10 | **WorkflowInstance / WorkflowApprove 里的网关分流逻辑确认已全部 skip** | 后端 workflow | 摘要里提到「两个独立类都要加 skip」——需确认 WorkflowInstanceServiceImpl.resolveGatewayBranch() 和 WorkflowApproveServiceImpl.resolveNextNodes() 里的 WorkflowNode 查询都已用 skip 包裹 |
