一、功能定位
平台侧 / 租户侧多个管理页面（用户、角色、工作流、表单等）统一复用的左侧可折叠组织架构树筛选面板。核心能力：

虚拟化树（el-tree-v2）支持万级节点流畅滚动
三种身份场景自动权限裁剪（root 超管 / 平台主体 / 租户账号）
模糊搜索 + 祖先链自动展开 + 高亮
拖拽分割线调宽度 + 折叠切换 + 响应式自适应
状态标记：冻结租户置灰、经营单元（isBizUnit=1）打标

R<List<OrgNodeVO>> getOrgTree() {
Long principalTenantId = SecurityUtils.getPrincipalTenantId();

    if (principalTenantId == null) {
        // 场景1：root 超管（tenantId 为 null 或 0 视具体实现）
        // → 查全部租户 + 全部部门 → 构建 platform-root 虚拟节点
        return buildFullTree();
    }
    
    if (isPlatformPrincipal(principalTenantId)) {
        // 场景2：平台主体账号（JWT claim platformPrincipal=true）
        // → PrincipalTenantScopeService.listScopedTenantIds(userId) 取授权范围
        // → 只查这些租户的部门
        return buildScopedTree(scopedTenantIds);
    }
    
    // 场景3：租户账号（tenantId > 0）
    // → CustomTenantHandler 自动隔离，只查当前租户部门
    // → 不返回租户层级，直接部门树
    return buildTenantDeptTree(principalTenantId);
}

3.4 前端：OrgTreePanel.vue 核心实现要点
模块	实现	为什么
虚拟化树	el-tree-v2 + :height="treeHeight"	必须给固定 height 才能虚拟化滚动
节点 key 映射	treeProps: { value: 'nodeId' }	⚠️ el-tree-v2 用 props.value（默认 "id"）取 key，不认 node-key prop
展开状态管理	ref expandKeys + :default-expanded-keys + @node-expand/collapse	el-tree-v2 不认 :expand-keys，只认 default-expanded-keys；没有 @expand-change 事件
手动折叠混乱修复	userCollapsedKeys（Array）+ effectiveExpandKeys 移除折叠节点及其子孙中间节点	el-tree-v2 的 setExpandedKeys 会自动补齐祖先链，如果只移除父节点不移除子孙，子孙会把父节点又展开回去
搜索过滤	computed displayTreeData 做 prune 剪枝（保留命中节点+所有未命中但有命中子孙的祖先）	不是用 el-tree-v2 的 filterMethod（因为拿不到内部 expandKeys 方法）
搜索后祖先链自动展开	prune 后只剩命中分支 → collectAllExpandKeys 收集中间节点 → 全展开	完美绕过 el-tree-v2 没有 expandNode API 的限制
拖拽分割线	增量 delta = clientX - startX + body cursor/userSelect 锁定	用绝对坐标会被系统菜单偏移污染
组件暴露	defineExpose({ reset() })	父页面重置按钮调用，清空搜索/选中/折叠

四、踩坑日志（必看！）
坑 1：el-tree-v2 的 key 字段名不匹配 → 整树折叠乱序
现象：点一个三角，其他租户也展开了；搜索后整树折叠。

根因：el-tree-v2 用 props.props.value（默认 "id"）取节点 key。后端节点字段叫 nodeId 不是 id。treeProps 里只设了 label/children，没设 value → 所有节点 key = undefined → expandedKeySet = Set { undefined }（Set 只能一个 undefined）→ 删一个 undefined 就清空整个 Set。

修复：treeProps: { value: 'nodeId', label: 'label', children: 'children' }

坑 2：el-tree-v2 的 prop 名称和普通 el-tree 不一样
你以为 el-tree-v2 支持	实际上
:expand-keys	❌ 不认！ 只认 :default-expanded-keys
node-key="xxx"	❌ 不认！ 在 treeProps.value 里设
@expand-change	❌ 没有这个事件！ 只有 @node-expand / @node-collapse，且只传 (nodeData, nodeInstance)，不传完整 expandKeys 数组
源码位置：node_modules/element-plus/es/components/tree-v2/src/composables/useTree.mjs

js



// 关键行为
const valueKey = computed(() => props.props?.value || "id")
// 每次 data 变化强制走：
setExpandedKeys(props.defaultExpandedKeys || [])
坑 3：setExpandedKeys 自动补齐祖先链 → 手动折叠混乱
现象：点租户 B 的折叠三角，租户 A 和 C 的子节点展开了。

根因：setExpandedKeys 源码会自动补齐祖先链。用户折叠 tenant-B 后，我们只从 effectiveExpandKeys 里移除了 tenant-B，但 tenant-B 下的 dept-X、dept-Y 还在里面 → 遍历 dept-X 时自动补齐 tenant-B → tenant-B 又被展开了！

修复：用户折叠一个节点时，同时移除它的所有子孙中间节点（collectDescendantExpandKeys）。

坑 4：租户侧 404 /tenant/org/tree
现象：租户账号登录，左侧树空白，network 报 /tenant/org/tree 404。

根因：前端 api/org.js 做了 getLoginType() === 'tenant' ? '/tenant' : '/system' 的前缀判断。但后端 只有 /system/org/tree 一个端点，内部通过 SecurityUtils.getPrincipalTenantId() 自动裁剪权限，不需要前端区分前缀。

修复：api/org.js 统一走 /system/org/tree。

坑 5：nginx 正则白名单漏了新模块 → 返回前端 SPA
现象：apifox 测 /system/org/tree 返回的是 HTML <title>CyanBase...</title>。

根因：nginx 配置里 API 代理用的是模块名白名单正则：

nginx



location ~ ^/system/(user|role|dept|tenant|...)/(.*)$
新增的 org 不在列表里 → 没命中任何 API location → 落到 try_files /index.html。

修复：加 org 到白名单。每次后端加新模块都要记得改 nginx！（长期方案：所有后端统一 /api 前缀）

坑 6：Lombok annotationProcessorPaths 覆盖 SPI 发现
现象：改了一个新功能，原代码未动，WorkflowInstanceServiceImpl 的 getDeptId()/getId()/log 突然全部报找不到。

根因：pom.xml 里显式声明了 annotationProcessorPaths，覆盖了 Lombok 的 SPI 自动发现。mvn clean compile 时 Lombok 偶发没跑。

修复：删除 annotationProcessorPaths 块，恢复 Spring Boot parent POM 的标准编译流水线。

坑 7：CustomTenantHandler.skip/reset 不配对 → 租户数据泄露
规则：所有 skip() 必须在 try-finally 里配对 reset()。本次改动全部遵守。

五、隐性约束
#	约束	来源
1	el-tree-v2 必须给固定 :height，否则无法虚拟化滚动	源码设计
2	后端节点字段名不能叫 id（和现有系统冲突），必须统一用 nodeId	后端约定
3	effectiveExpandKeys 必须是中间节点集合（有 children 的 nodeId），叶子节点不需要	setExpandedKeys 源码只对中间节点有意义
4	搜索用前端 prune 剪枝，不能用 el-tree-v2 的 filterMethod	filterMethod 会隐藏节点但无法控制展开状态
5	nginx API 代理用模块名白名单正则，加新模块必须改配置	运维配置
6	SecurityFilterChain /system/** 放行 + JWT 过滤器 → 租户身份 token 能正确识别	安全配置
7	deptIdIncludeChildren 必须和 tenantId 同时传	防止跨租户越权

场景	怎么做	风险点
新增后端业务模块（如 /system/featureX/*）	nginx 白名单正则加 featureX	漏加 → 返回前端 SPA → 调试半天
