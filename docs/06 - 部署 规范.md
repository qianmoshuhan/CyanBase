# 部署规范

---

## 1. 典型架构

```
nginx (38024)
  ├── / → 前端 dist（try_files $uri /index.html）
  ├── /auth/**          → proxy_pass Spring Boot :8090
  ├── /tenant-auth/**   → proxy_pass Spring Boot :8090
  ├── /tenant/**        → proxy_pass Spring Boot :8090
  ├── /workflow/**      → proxy_pass Spring Boot :8090（⚠️ 精确 regex！见第 2 节）
  └── 其他 API 前缀      → proxy_pass Spring Boot :8090
```

---

## 2. ⭐ SPA 刷新 404 问题（必须修！）

### 根因

前端 history 模式路由（如 /workflow/start），浏览器 F5 刷新时 nginx 按真实路径找文件 → 找不到 → 404。

### nginx 修复

```nginx
# ✅ 必须用 try_files 兜底，放在 location / 里
location / {
    try_files $uri $uri/ /index.html;
}

# ❌ 绝对不能让 API 前缀 regex 接走纯前端路由
# 错误示例：
# location ~ ^/workflow/ { proxy_pass ... }
# 会把 /workflow/start（纯前端路由）也代理给后端 → 404

# ✅ 正确：精确匹配后端 Controller 真实路径
location ~ ^/workflow/(approve|instance|definition|node|copy)($|/) {
    proxy_pass http://127.0.0.1:8090;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

### 需要精确 regex 的 API 前缀

| 前缀 | 后端 Controller 真实路径 | regex |
|---|---|---|
| workflow | /approve, /instance, /definition, /node, /copy | `workflow/(approve\|instance\|definition\|node\|copy)` |
| tenant | 全部接口 | `tenant/**`（安全，全匹配没问题） |
| auth | 全部接口 | `auth/**` |
| system | 全部接口 | `system/**` |

> workflow 特殊：后端 Controller 只有 /approve、/instance（含 POST /instance/start）、/definition、/node、/copy 这几个路径。但前端纯路由 /workflow/start 也以 workflow 开头。所以必须精确 regex，不能全匹配。

## 3. nginx 完整配置模板

```nginx
server {
    listen 38024;
    listen [::]:38024;
    server_name _;

    root /usr/share/nginx/html/cyan;
    index index.html;

    # ⭐ SPA 兜底（放最前面！）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反代（精确匹配后端 Controller 路径）
    location ~ ^/(auth|tenant-auth|system|tenant|monitor|wf|log|form|upload|api|actuator)($|/) {
        proxy_pass http://127.0.0.1:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    location ~ ^/workflow/(approve|instance|definition|node|copy)($|/) {
        proxy_pass http://127.0.0.1:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 禁止浏览器缓存（开发阶段方便调试）
    add_header Cache-Control "no-store, no-cache, must-revalidate" always;
}
```

改完后 `nginx -t && nginx -s reload`。

## 4. 后端 Spring Boot 部署

```bash
# 本地打包
cd cyanbase-backend
mvn clean package -DskipTests

# 服务器运行
java -jar target/cyanbase-backend.jar

# 推荐用 systemd / 守护进程托管
# 端口 8090，MariaDB + Redis 确保启动
```

## 5. 前端部署

```bash
cd cyanbase-frontend

# 开发模式（本地调试）
npm run dev

# 生产构建
npm run build
# 产物：dist/ 目录

# 服务器部署：把 dist/ 拷到 nginx 静态目录
scp -r dist/* user@server:/usr/share/nginx/html/cyan/

# ⚠️ 每次改前端都必须重新 build + scp
```

## 6. 常见部署故障排查

| 现象 | 可能原因 | 排查命令 |
|---|---|---|
| F5 刷新前端路由 404 | nginx 没配 try_files 或被 API regex 接走 | 直接访问 nginx 看返回是不是 index.html |
| 翻页显示一样数据 | 前端没显式 handlePageChange / 后端分页拦截器没生效 | curl page1 和 page2 对比 records |
| 新权限不生效 | Redis 缓存没清 | `redis-cli KEYS "rbac:*" \| xargs redis-cli DEL` + 重新登录 |
| 按钮 v-perm 隐藏了但接口还是 403 | 前端权限没联动 | 看登录返回的 permissions 数组 |
| approve 表同一人多条记录 | 审批时 INSERT 没 UPDATE | DELETE 脏数据（见 workflow.md） |
| 启动报 NoUniqueBeanDefinitionException | TenantMybatisPlusConfig 的 @Primary 漏了 | 加 @Primary |
| 审批被拒提示 workflow:approve 权限缺失 | sys_menu 里没插 menu_type=3 的 workflow:approve 按钮 | INSERT INTO sys_menu(...) VALUES (..., 'workflow:approve', 3, ...) |
