# CyanBase 青渊数字底座 底座完善【阶段一 专属开发任务单】

## 阶段一：全局异常重构 + 统一全局错误码体系开发

承接上方完整版底座完善手册，当前只执行**第一阶段开发内容**，指令独立拆分，直接发给后端 AI 执行，严格约束开发规则，不改动原有业务代码。

## 一、阶段一开发约束规则

1. 禁止修改已有稳定业务代码：JWT 认证、登录鉴权、用户角色部门菜单 CRUD、MP 配置、跨域配置、原有统一返回类`R`全部保留。
2. 全部采用**新增文件、新增类**方式开发，无代码覆盖替换。
3. 统一编码风格、类命名、包层级完全贴合现有 CyanBase 后端开发规范。
4. 完成后原有接口功能不受任何影响，仅优化异常捕获与错误返回格式。
5. 异常信息标准化，去除代码内所有硬编码错误提示文字。

## 三、具体开发内容明细

### 3.1 全局统一错误码枚举开发

1. 创建枚举类 `ResultCodeEnum`
2. 按照规范划分多级业务错误码，码值区间严格定义
- 系统基础码：`10000 ~ 19999`
- 认证权限码：`20000 ~ 29999`
- 用户角色部门码：`30000 ~ 39999`
- 字典配置模块码：`40000 ~ 49999`
- 文件存储专用码：`50000 ~ 59999`
- 定时任务专用码：`60000 ~ 69999`
- 消息公告专用码：`70000 ~ 79999`
- 工作流表单扩展码：`80000 ~ 89999`
1. 枚举固定属性：状态码 code、提示信息 msg
2. 兼容原有成功状态 `200`、未授权 `401`、服务异常`500`

### 3.2 分层自定义业务异常封装

新增细分异常实体，分类精准抛出异常

1. 基础全局异常 `BaseException`
2. 业务自定义异常 `BusinessException`
3. 认证授权异常 `AuthException`
4. 参数校验异常 `ParamValidException`

所有自定义异常支持传入**错误码枚举**进行构造。

### 3.3 全局统一异常拦截处理器

创建 `GlobalExceptionHandler` 全局异常处理类

1. 拦截处理：自定义业务异常、认证异常、参数异常
2. 拦截处理：系统未知运行异常、空指针异常
3. 拦截处理：参数校验异常、请求格式异常
4. 所有异常统一封装为标准`R`返回格式，和业务接口返回结构完全一致
5. 控制异常日志打印级别，业务异常精简日志，系统异常完整打印堆栈信息

### 3.4 改造现有返回工具类

1. 优化`R`工具类，新增通过**错误码枚举**快速构建失败返回的静态方法
2. 保留原有所有旧方法，保证历史代码完全兼容不报错
3. 后续所有业务报错全部统一使用枚举错误码，杜绝字符串硬编码

### 3.5 基础请求参数全局校验整合

1. 引入 JSR380 参数校验注解依赖
2. 开启实体类参数校验能力
3. 全局异常处理器接入参数校验异常捕获，统一友好返回提示

## 四、配置与依赖新增要求

仅在 pom.xml 追加参数校验依赖，其余依赖不做改动，原有配置全部保留不变。

## 五、编译验收标准

1. 执行 `mvn clean compile` 编译无报错
2. 启动项目正常启动，无启动异常
3. 手动制造异常场景，能够被全局异常拦截捕获
4. 异常返回数据格式统一标准化，携带对应错误码
5. 历史登录、所有原有业务接口访问不受影响
